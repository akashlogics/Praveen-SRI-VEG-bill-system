# SRI K.M. VEGETABLES — Billing & Ledger (Supabase + Render)

This is the version migrated from the localStorage version to Supabase. You can view the same data on both mobile and laptop in an auto-synced state. Secured with a single shop PIN.

---

## 📦 What Changed

| Feature | Old Version (localStorage) | This Version (Supabase) |
|---|---|---|
| Data Location | Separately on each browser | Single Supabase database, common to all devices |
| Mobile ↔ Laptop Sync| No (manual JSON export/import) | Automatic (both look at the same DB) |
| Login | No | Single shop PIN (via Supabase Auth) |
| Hosting | On any static host (like Netlify) | Render (Node/Express Server) |
| Bill Logo | Generated by text | Your original letterhead image (`assets/logo.png`) |
| Bill Share | WhatsApp + Print buttons | "Save Bill" (image download) + "Share" — to any app, including 3-inch thermal printer apps |

## 🚀 Setup — Step-by-Step

### Step 1: Create a Supabase Project

1. Go to [supabase.com](https://supabase.com) → New Project.
2. Once the project is created, choose **SQL Editor** in the left sidebar → New Query.
3. Copy the entire contents of the `supabase/schema.sql` file, paste it into the editor, and click **Run**.
   - This will create 5 tables (`shop_settings`, `items`, `customers`, `bills`, `payments`), insert the default vegetable list, and set up Row Level Security (RLS) rules.
   - Running this again is safe (`IF NOT EXISTS` / `ON CONFLICT`).

### Step 2: Create a Single Shop PIN

1. In the Supabase Dashboard, go to **Authentication** → **Providers** → find **Email**, and turn the **"Confirm email"** setting **OFF** (otherwise login won't work since the login email is a placeholder and not a real mailbox).
2. Go to **Authentication** → **Users** → **Add user** → **Create new user**.
   - Email: `shop@sri-km-vegetables.local` (You can use any valid email string here, but it must match exactly with the `loginEmail` in `public/config.js`).
   - Password: **This is the shop PIN** — for example, `2580` or `Srikm2026` — whatever the owner needs to use in the shop, enter it here.
   - Check **"Auto Confirm User"** ✅.
3. To change the PIN later: click on the user in the Users list and select "Reset Password".

### Step 3: Fill in `public/config.js`

From the Supabase Dashboard → **Project Settings** → **API**:

```js
const SUPABASE_CONFIG = {
  url: 'https://xxxxxxxxxxxx.supabase.co',   // "Project URL"
  anonKey: 'eyJhbGciOiJI...',                 // "anon" "public" key (Project API keys)
  loginEmail: 'shop@sri-km-vegetables.local'  // The exact email created in Step 2
};
```

> ⚠️ **Never use the `service_role` key here** — it has admin-level access to the entire database and must be kept secret on the server-side. Only the `anon` key is safe for the frontend (security is enforced via RLS policies, not by hiding this key).

### Step 4: Deploy on Render

1. Push this `skv-supabase` folder as a new repository to GitHub (under your `akashlogics` account).
2. Go to [render.com](https://render.com) → **New** → **Web Service** → select that repository.
3. Settings:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Environment**: Node
4. Once deployed, Render will provide a URL (e.g., `https://sri-km-vegetables.onrender.com`) — share this URL with the shop owner (instruct them to use "Add to Home Screen" on their mobile device so it looks/feels like a native app).

> 💡 **Render free tier note**: If inactive for a while, it goes to sleep and the first load will experience a "cold start" delay. If needed, you can set up a ping every 10-14 minutes on cron-job.org to keep it awake.
> **Supabase free tier**: If not used for 7 days, the project pauses. Set up a ping every 2-3 days via cron-job.org to prevent this.

## 🔑 How to Use (For the Shop Owner)

1. Open the URL (on mobile or laptop) — a PIN screen will appear.
2. Enter the PIN you configured during Setup → click "Login" ("நுழை").
3. Once logged in, any bill entered on the mobile device will immediately be visible on the laptop after a refresh.
4. To sign out, click the "🔒 Logout" ("🔒 வெளியேறு") button in the sidebar.

### Bill → Save/Share Flow

- Create a bill and click "Save & View Bill" ("பில் சேமி & காண்பி") to see the preview.
- **💾 Save Bill**: Downloads the bill as an image (PNG) on the mobile device / PC.
- **📤 Share**: Opens the mobile device's native sharing sheet — from here, you can choose WhatsApp, Bluetooth, or any thermal printer app (e.g., RawBT). The printer app receives the bill as an image and prints it directly.
- If Web Share is not supported in desktop Chrome, it will automatically download as an image, which can then be shared/sent manually.

## 🔧 For Developer (Notes)

### Auth Design — Why this setup?
Since a single shared "shop PIN" is required, a single Supabase Auth user (configured with the `loginEmail` in `config.js`) has been created, and their password acts as the shop PIN. RLS policies for all tables check `auth.role() = 'authenticated'` — meaning anyone who is logged in (yes/no check, without individual row ownership) has read/write access. This provides sufficient security for a single-shop, single-shared-login app. If separate staff logins are needed in the future, a `user_id` column can be added to the tables to enforce per-row owner RLS.

Exposing the `anon` key in the frontend is intentional — this is the expected pattern in Supabase's architecture; security is enforced by RLS policies, not by trying to hide this key.

### Data Layer Design
The rendering logic in `app.js` is unchanged — `shop`, `items`, `customers`, `bills`, and `payments` still exist as in-memory arrays with the same names. Upon logging in, `DB.fetchAll()` populates these arrays. For every add/edit/delete operation, the corresponding `DB.upsertX()` or `DB.deleteX()` is called, and then the local array is updated (optimistically — the UI updates once the Supabase call succeeds).

- `bills`, `payments` — insert-only from the UI (no edit or delete, keeping previous behavior). The "Data Cleanup" feature performs bulk deletes (`DB.deleteBillsBefore` / `deletePaymentsBefore`).
- The ledger balance calculation remains the same: `openingBalance + Σ bills − Σ payments`, as described in the localStorage version of the app.
- The creation time `createdAt` (ms timestamp) is saved directly in `bills.created_at_ms` and `payments.created_at_ms` columns to preserve sorting order in the dashboard/reports.

### Files Touched for this Migration
- `public/config.js` — **New**, Supabase project settings.
- `public/db.js` — **New**, Full Supabase read/write layer.
- `public/app.js` — localStorage `load()` and `save()` calls were replaced with `DB.*` async methods, and a login/boot flow was added to the end of the file ("AUTH / BOOT" section).
- `public/index.html` — Login screen UI markup, `#appShell` container wrapper, and the Supabase-js CDN script tag.
- `server.js`, `package.json` — **New**, Minimal Express static server for Render deployment (not required for the data layer, but aligns with standard subfolder deployment conventions on Render).
